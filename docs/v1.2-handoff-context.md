## 本轮主要目标

本轮没有处理结局触发系统。当前重点是先把 AI Agent 的上下文边界收紧：

1. 统一 harness 架构。
2. 建立 Agent Contract 与 Agent Trace。
3. 做结构化记忆系统。
4. 做 ContextBuilder。
5. 做 World Info Lite。
6. 把 World Info 接入各 Agent 上下文。
7. 把 World Info 命中结果写入 Agent Trace。
8. 让 Killer / Narrator prompt 真正消费 World Info。
9. 修复 Killer 信息泄露问题。

### Killer 信息泄露修复

用户测试时发现问题：

玩家检查纸板箱后，看到了药片/药板，但门外的人不应该知道玩家看到了药片。实际叙事里却出现短信：“别碰药片，把箱子放回门口。”

审查结论：

这不是 RuleEvent visibility 直接标错，而是 Killer AI 输入边界泄露。Killer AI 虽然有 `killerContext`，但 server payload 还同时传了完整 `plan` 和完整 `playerResult`。`playerResult.text` 里包含“药板”等玩家私密发现，导致 Killer 能读到。

已修复：

- Killer AI prompt payload 现在只传 `killerContext`。
- 不再传完整 `plan`。
- 不再传完整 `playerResult`。
- `killerContext.planSummary` 不再使用玩家原始动作摘要。
- `killerContext.planSummary` 只从 `visibility === 'killer'` 的可观察事件生成。
- Killer 的 World Info 检索也只使用 killer 可见事件。
- `updateKillerKnowledgeFromState()` 不再因为 `room.package.state.opened = true` 就让凶手确定知道玩家打开包裹。
- 只有传入 killer 可见事件时，才升级 `knowsPlayerOpenedPackage` / `knowsPlayerPhotographedPackage`。

新增回归测试：

- Killer prompt payload 中不能出现：
  - `药片`
  - `药板`
  - `package contents`
  - 玩家原始动作文本
  - 完整 `playerResult.text`

关键文件：

## 重要工程约束

新对话继续开发时请注意：

1. 先不要设计或修改结局触发逻辑，除非用户明确要求。
2. 目前重点是 Agent 上下文边界、Killer 可见知识、World Info 命中质量和叙事一致性。
3. 不要让 Killer 读取完整 `GameState`、完整 `playerResult` 或玩家原始输入。
4. Killer 只能依据：
   - `killerContext.visibleState`
   - `killerContext.observableEvents`
   - `killerContext.recentKillerMemory`
   - 允许给 Killer 的 `worldInfo`
   - `killerContext.uncertainty`
5. Narrator 可以看叙事所需上下文，但不能改变规则结果。
6. World Info 不是规则裁判，不能直接判定行动成功、生死、结局或状态变更。
7. 新增测试优先覆盖“信息边界是否泄露”，尤其是 Killer 是否知道玩家私密行动。

## 下一步建议

### 优先级 1：继续测试 Killer 信息边界

建议做一组实际玩法回归测试，覆盖：

- 玩家检查包裹但没有发出明显声音，Killer 不知道药片/药板。
- 玩家拍照但手机静音且未发送，Killer 不知道照片内容。
- 玩家把照片发给林越，Killer 默认不知道林越已收到，除非有可观察事件或已建立监听渠道。
- 玩家堵门发出明显噪音，Killer 可以知道门被处理，但不能知道房内具体操作细节。
- 玩家开灯/手机亮屏，Killer 可以察觉光线变化，但不能知道发送给谁、发了什么。

推荐新增位置：

- `packages/game-core/src/context/ContextBuilder.test.ts`
- `apps/server/src/ai/killerPrompt.test.ts`

### 优先级 2：让 Agent Trace 更方便调试

当前 trace 已记录 World Info 摘要，但普通 UI 不展示。

下一步可以做开发模式调试面板：

- 仅在 dev/debug 模式显示。
- 默认折叠。
- 展示每个 Agent 本回合命中的 World Info ID。
- 不展示卡片正文，避免污染玩家体验。

注意：不要默认展示给玩家 demo。

### 优先级 3：调 World Info 触发质量

等 trace 可观察后，再调：

- trigger keywords
- priority
- limit
- agent visibility

不要凭感觉先大改卡片内容，应先看实际命中情况。

### 优先级 4：继续收紧 Killer 长期策略

当前 Killer 已不再全知，但长期策略仍偏单步选择。

后续可以引入：

- Killer objective
- Killer suspicion model
- Killer risk tolerance
- Killer failed-attempt memory
- Killer observable history

但这些应建立在当前信息边界稳定之后。

### 优先级 5：再处理结局触发系统

结局触发模糊是已知痛点，但本轮暂未处理。

未来建议方向：

- 不要把所有结局写成死硬编码。
- 可以先做“结局候选评估 + 证据/风险/状态评分 + Director 审查”。
- 规则系统仍保留最终裁决权。
- Narrator 不得直接写死结局。

## 给新对话的第一步建议

如果新对话继续开发，建议先从这个任务开始：

> 为 Killer 信息边界补一组端到端回归测试，复现“检查包裹看到药片，但门外人不能知道药片”的场景，并确认实际 server prompt payload 与 Agent Trace 都不泄露私密信息。
