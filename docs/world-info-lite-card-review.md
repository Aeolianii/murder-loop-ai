# World Info Lite Card Review Draft

这份文档是人工校验清单，不是运行时规则来源。确认后的内容再回填到 `packages/content/src/worldInfo.ts`。

## 校验等级

- `必须人工校验`: 会影响规则边界、凶手知识、警察/结局相关判断。
- `建议人工校验`: 会影响叙事稳定性或 Agent 行为倾向。
- `自动派生可接受`: 主要来自 `room.ts` / `clues.ts` / `npcs.ts`，通常只需检查名称和关键词。

## 必须人工校验：规则卡

| id | 建议标题 | 草稿描述 | 校验点 |
| --- | --- | --- | --- |
| `rule.killer_visibility` | 凶手信息边界 | 陈怀民不能天然知道玩家的私密行动。只有当规则事件、`killerKnowledge`、可观察物理痕迹或已建立的监听/目击渠道支持时，他才可以据此行动。 | 确认“照片发给林越”“手机藏哪了”“玩家内心判断”默认不对凶手可见。 |
| `rule.door_window_boundary` | 门窗防御互不替代 | 堵门、上门链、反锁前门只影响 `front_door`。窗户路线必须单独检查 `window` 的锁、窗帘、检查状态，不能因为门被堵住就自动安全。 | 确认防盗链/椅子/门锁不会自动阻止窗户入侵。 |
| `rule.police_verification` | 警察身份核验 | 门外自称警察不等于真警察。玩家需要通过官方渠道、报警回拨、调度信息或可信证据核验身份。 | 确认假警察和真警察的判断不靠叙事 AI 临场决定。 |
| `rule.narrator_no_rule_change` | 叙事不能改规则 | Narrator 只能表达规则结果，不能新增死亡、逮捕、逃脱、关键线索、角色到场或物品状态变化。 | 确认叙事输出中的 `ending/isFatal/killerKilled/clue` 仍只作为建议或受代码审核。 |
| `rule.world_info_not_authority` | World Info 不是规则裁判 | World Info 只提供设定上下文，不直接判定行动是否成功、生死、结局或状态变更。最终状态只能由规则系统和已确认事件改变。 | 防止“卡片里提到可逃脱”被 AI 当成逃脱成功。 |

## 必须人工校验：关键物品卡

| id | 建议标题 | 草稿描述 | 校验点 |
| --- | --- | --- | --- |
| `object.package` | 标记模糊的包裹 | 包裹位于桌边，是误收事件和证据链的核心物品。它可能被打开、拍照、隐藏或恢复原状，但包裹内容和证据有效性必须由规则/线索确认。 | 包裹是否能被销毁、藏匿、复原？拍照是否一定生成证据？ |
| `object.front_door` | 入户门 | 入户门位于玄关，是敲门、开门、反锁、门链、防堵和强入压力的主要交互点。它不代表窗户或其它入口的安全状态。 | `locked/chainLocked/barricaded/scratched/opened` 每个状态的真实含义。 |
| `object.window` | 窗户 | 窗户位于卧室墙面，和窗帘、锁、外部路线有关。窗户是否安全必须看 `window` 自身状态，不能从门的状态推断。 | 窗户能否逃生？能否被凶手利用？需要哪些前置检查？ |
| `object.phone` | 手机 | 手机可用于拍照、录音、通信和报警，但受电量、静音、是否可用等状态限制。手机行为不应自动对凶手可见。 | 低电量、录音、拍照、报警是否都有明确代价和可见痕迹？ |
| `object.phone_charger` | 手机充电器 | 充电器位于桌边，可影响手机续航。是否能充电取决于插入状态、电源条件和玩家动作是否成立。 | 断电/插座/充电速度是否已有规则支持？ |
| `object.chair` | 椅子 | 椅子可移动，可能参与堵门或制造噪音，但不能自动成为万能防御或稳定武器。 | 椅子堵门的强度、耗时、噪音、风险。 |

## 自动派生可接受：基础卡说明

这些卡可以继续由生成器从结构化数据自动生成，人工只需检查关键词是否容易触发：

- `object.phone_charger`
- `object.closet`
- `object.bed`
- `object.bathroom`
- 普通 `clue.*` 卡的标题、权重、持久性
- `story.core`

## 建议新增人工规则卡

| id | 草稿描述 | 原因 |
| --- | --- | --- |
| `rule.phone_visibility` | 手机亮屏、按键声、通话声可能被外部察觉，但“发给谁、发了什么、藏在哪里”默认不可见。 | 细化 Killer 可观察事件。 |
| `rule.evidence_backup` | 外部备份只有在通信成功、接收者可信、证据内容足够清楚时才有意义。 | 防止“发消息=必胜”。 |

| `style.no_player_mind_reading` | 叙事不能替玩家写“我意识到/我害怕/我决定”，只能写可观察动作和外部反馈。 | 稳定第一人称有限视角。 |
